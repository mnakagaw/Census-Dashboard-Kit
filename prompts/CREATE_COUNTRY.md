# 国名だけで開始する完成版プロンプト

> Canonical prompt: [`ONE_COUNTRY_COMPLETE.md`](ONE_COUNTRY_COMPLETE.md). Change only `COUNTRY_NAME`; this file remains a detailed Japanese reference.

短い依頼で開始できる。利用者が指定するのは国名でよく、既存の案件指示がある場合は併せて使う。

```text
https://github.com/mnakagaw/Census-Dashboard-Kit を参照して、［国名］版をこの一回の依頼で完成させて。途中の生成画面を成果として返さず、納品ゲートに合格した完成品だけを見せてください。
```

AIへ作業範囲を詳しく渡す場合は、次を使用する。

```text
対象国：［国名］
参照リポジトリ：https://github.com/mnakagaw/Census-Dashboard-Kit

このPublicリポジトリを読み取り、START_HERE.mdとAGENTS.mdから作業を始めてください。国名を正規化し、既存案件の指示・保存先・資産を確認してください。AIが調べて埋められる項目を私への質問票にせず、国を一意に特定できない等、成果が変わる重要な曖昧さだけ確認してください。

docs/COUNTRY_AGENT_WORKFLOW.md、docs/IMPLEMENTATION_CONTRACT.md、共通仕様C01～C07、国別データ適応規則に従ってください。DDPTの「地域から多分野を読む」「テーマから地域間を比較する」の目的、情報配置、地域選択の連動、出典と欠測、計画資料への経路を維持してください。善意の独自変更で主要導線や操作の意味を変えないでください。

新しい出力先へcreate-country.mjsを実行してAI用の内部作業場所を準備してください。この時点でサイトを開いて私へ返答せず、そのまま現地統計局、国勢調査、公式地域コードと行政区分、地方計画・計画様式、公開予算・事業、取得可能な住民参加資料を調べてください。同条件で利用できる国内の公式一次資料を優先してください。

生成されたevidence/SOURCE_PREFLIGHT.mdと.jsonを読み、事前登録された国別sourceの新版・内容を確認してください。国別登録がなければ国勢調査、計画法、計画手引き、公式計画、地域コード・境界の所在を先に調べて台帳へ残してください。国際共通sourceは対象国・テーマ・年・地域粒度のavailabilityを確認してから取得し、所在確認、取得、地理照合、指標採用を別の段階として記録してください。再利用できる原本・取得receipt・変換結果は利用条件に従って版管理し、認証情報や再配布不可資料をGitへ保存しないでください。

docs/PLANNING_CENSUS_METHOD.mdを読み、templates/PLANNING_CENSUS_AUDIT.mdを案件へコピーして記入してください。まず計画法・自治体法・州法等の名称、制定年、参照改正年、所管・作成・承認主体を調べ、計画策定を担う地方自治体と計画区域を特定してください。統計の最小区分やADM2を法定主体として固定しないでください。国勢調査の基礎指標をその単位でそろえ、法定診断項目・地域課題に足りないテーマから省庁別資料へ探索を広げてください。最新実施年と採用詳細年、全数・標本・補正、設問の存在・公表・原表取得・統合検証を区別してください。資料と診断、協議で確認された要求、事業候補、計画草案、実施と見直しを根拠IDでつなぎ、住民の合意や目標・事業費・公式承認は創作しないでください。

公開API、Excel、PDF等から実際に資料を取得し、docs/SOURCE_ADAPTER_GUIDE.mdに沿った再実行可能なアダプターで地方値と計画資料をデータ契約へ追加してください。コード体系と境界版を根拠で照合し、provider IDを公式コードと扱わないでください。全国値の地方への代用、出典のない推定、欠測のゼロ化、未取得資料からの計画不存在・承認判定をしないでください。

docs/AI_FAILURE_MODE_REVIEW.mdを読み、最初に見つかった人口ファイルだけで探索を終了しないでください。統計局の国勢調査目録・付表・地域統計書・API、所管省庁の行政統計、MICS／DHS／LSMS等の公式共同調査、OCHA/HDX、国際機関の地域別公表値、IPUMS IHGIS等を確認してください。人口、教育、保健・栄養、水・衛生・住宅・エネルギー、生計・貧困・経済、アクセス・インフラ・環境の6分野について、候補の発見・原本取得・地理照合・採用を分けて記録してください。候補を発見したまま未統合なら完成ではありません。統合するか、地域照合・定義・ライセンス・品質等の具体的な制約と代替を記録してください。

Excelは全シート、CSV／APIは全フィールド、PDFは目次・付表・継続表を調べてください。`templates/SOURCE_TABLE_INVENTORY.json`を案件へコピーし、全数値列の原名、意味、単位、分母、地域粒度、期間、採用指標IDまたは非採用理由、各source原本の再配布判断を記録してください。再配布不可・要許諾の原本をPublic成果へ含めません。画面へ載せる数だけを台帳へ書くことは禁止します。`templates/THEME_COVERAGE.json`も案件へコピーし、6分野をすべて確定状態にしてください。

取得可能な情報の粒度・期間・頻度に合わせて図表と機能を適応してください。地図なしなら一覧、時系列なしなら実在する時点を使い、保留機能には理由と代替作業を示してください。

その国の計画法令、施行規則、所管機関の策定手引き、公式様式を確認し、計画書の必須目次・章・表・記入欄を出典箇所付きで`planning.document_template`へ登録してください。公式の固定目次がない場合だけ、その事実の根拠を示し、確認した法定要求を各章へ対応付けた目次を作ってください。一般的な章立てを国別確認なしに流用しないでください。選択地域の統計、資料、出典、不足欄を含む編集可能なDOCXを必須出力にし、実ファイルを隔離レンダラーで全ページ確認してください。

Development Plan Materialsには、①適用法令・公式手引き、②国勢調査・統計局の原表、③採用した国際機関データを区分して、公式リンク、発行主体、取得状態、確認日付きで一覧表示してください。同じ出典一覧をWordにも含めてください。

地方観測が一件でもある場合、初期表示は地方比較が成立する指標・年にしてください。全国系列しかない指標では、空の地域地図・凡例・全件表を画面に繰り返さず、短い不足説明と利用できる地方指標への導線を示してください。「全地域に少なくとも一件ある」という全期間・全指標の件数を、現在の指標・年の収録率に見えるよう表示しないでください。国勢調査実測、標本推計、投影、行政登録、国際推計は別系列として明示してください。

Territorial Diagnosticでは、選択地域の各テーマ・指標について取得・確認できた最も新しい値を自動表示し、値の横に実際の出典年を付けてください。年セレクター、過去年への切替、時系列グラフ、履歴CSVへの導線は国別3ページに置かないでください。Thematic Diagnosticの地域間比較は一指標・一階層・利用できる最新共通年へ自動で揃え、比較年を表示してください。選択地域の最新版が比較年と異なる場合は別表示として説明してください。地方値が0件のテーマと全国だけの文脈は折りたたみ、地方データのあるテーマを先に見せてください。選択可能階層の図形がなければ大きな空地図を置かず、短い不足表示と未結合一覧を残してください。表示言語ごとに操作文・見出し・状態文を確認し、固有名称以外の意図しない言語混在を修正してください。詳しくはdocs/LATEST_VALUE_POLICY.mdに従ってください。

Territorial Diagnostic、Thematic Diagnostic、Development Plan Materialsの3ページを基本構成にしてください。地域診断の既存上部の地域選択・基本情報・位置図は維持し、各指標の下部に、その選択範囲の構成地域を比較する地図と全件表を追加してください。全国を選択した場合も国内の構成地域を比較してください。国別に基礎自治体を確認し、通常の細分はそこで止め、街区・集落のデータがあっても自動で下位UIを作らないでください。

下位地域を選んだ後、ドロップダウンで現在の所属先と同じ上位地域を明示的に選び直した場合も、下位選択を解除し、指標・期間を保持して上位全体へ即時に切り替えてください。同じoptionの再選択で`change`が発火しない場合も回帰試験してください。下部比較のクリックは同じ指標内の注目箇所だけを変え、上部の分析対象、見出し、他指標、URL、資料、出力先を変えないでください。全体台帳に基づく比較集合、同じ統計年・定義・母集団・単位・境界版を確認し、率の平均や全国値の配分で親・地方の値を作らないでください。地図と全件表の対象を一致させ、欠測・地図なしの地域も表に残し、印刷では画面の検索・折畳み・スクロールに関係なく全対象行を出してください。既存20か国研究は探索資料として保持し、全数値取得・統合済みや新しいUIの実測結果と扱わないでください。

docs/ANALYSIS_DATA_CONTRACT.mdに従い、設計profileの判断をschema 0.2の任意analysisへ対応付けてください。旧データの直接の子を使う比較、市・自治体型等で停止する既定を国別に確認し、必要な全構成IDと細分停止IDを根拠付きで登録してください。意味が異なる観測は元のmetadata・値・出典・比較不可理由を保持し、国際と国内の異なる概念を別指標IDにしてください。診断Markdown・各指標の最新版を使う内部地図と全件表を含むHTML・指標別最新版と年を含む全件CSVを実取得して照合し、既存の計画出力も保持してください。

計画・予算／財政・実施報告・公式評価を調査の観点として確認し、制度名、対象階層、周期、会計年度、公式状態と尺度、資料ごとの取得・更新・利用条件をAIが記録してください。４区分を必須の同じカードやページにせず、SISMAP、ウガンダの章構成、５年周期を全世界に当てはめないでください。既存の投資・財政機能から同じ資料を参照する方法も使ってください。

docs/PLANNING_DATA_CONTRACT.mdを読み、設計用country-profileとruntimeのdata/dashboard.json内の任意のplanningを分けてください。公開された優先資料の本文を取得・抽出・原本照合し、地域の同定、対象期間、出典箇所を残してください。リンク確認、本文取得、内容確認と公式状態を分け、要約・課題・目標・財政・実施結果・評価は根拠のある範囲で表示・出力してください。評価点を執行率や達成率へ読み替えず、統計年で会計年度・複数年計画を隠さないでください。地図の既定は資料収録状況とし、公式状態の表示は対象区分・資料期間・状態定義と証拠を揃えた場合だけ採用してください。

実データのある地域と不足する地域で、地域選択→診断／比較→計画資料→採用出力が動作するローカルサイトを完成させてください。データ検証、ブラウザ操作、実際の取得物の地域・期間・単位・代表値・出典を確認し、結果と未検証範囲を記録してください。起動しただけ、リンクを収集しただけ、空欄中心の画面を作っただけで私へ返答しないでください。

確認済み資料・原本・変換処理・未結合・不足・次の取得行動を台帳へ残してください。資料不足時も取得済みの根拠・原資料・補完欄で作業できる代替を完成させてください。更新失敗時は最後の正常版を保持し、元資料の更新停止とサイト生成・配備の失敗を分けて説明してください。HANDOFF.mdに完了工程、途中工程、原本と抽出位置、再実行コマンド、最終成功版、次の具体的作業を保存し、再開時はそこから続けてください。内部作業場所だけの段階は収集途中として扱ってください。
```
