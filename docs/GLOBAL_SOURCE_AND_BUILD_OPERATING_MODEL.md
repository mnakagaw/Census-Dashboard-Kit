# 世界全体とJICA優先142か国・地域の運用モデル

## 結論

全世界分の完成データを人が先に集めてAIへ渡す方式にはしない。UN M49のcountry/area台帳と、JICA海外事務所の現行Purviewに掲載された**142か国・地域**の優先台帳を分けて保持する。原本の取得、表・列の棚卸し、地域照合、指標採用、サイトとWordの生成は、国別に再実行可能なアダプターで進める。

この分離により、古くなった国別原本を手作業で維持せず、優先台帳、国別source所在、取得済み、照合済み、公開済みを混同しない。国名だけの依頼は引き続き実行依頼であり、利用者へ資料収集を戻さない。

国別成果のディレクトリ名と公開URLのslugは、ISO 3166-1 alpha-3を小文字にして統一する。例はバングラデシュ`bgd`、ラオス`lao`である。画面上の国名や地域名は正式な表示名を使い、3文字コードをタイトルの代用にしない。

## 四つの層

| 層 | 世界台帳とJICA優先142で先に持つもの | 国別案件で追加するもの | 保存先 |
|---|---|---|---|
| 1. 所在台帳 | ISO/M49、国名、言語、統計局、国勢調査入口、行政コード・境界入口、計画法・手引き・計画資料入口、確認日 | 改組、改正、新版、アクセス条件の再確認 | Gitの`config`と調査記録 |
| 2. 取得アダプター | 共通sourceの仕様とavailability確認手順 | URL列挙、download、hash、receipt、PDF/Excel/API抽出、地域対応、採否 | Gitのコードと小さなfixture |
| 3. 証拠保管 | source ID、版、利用条件、保存規則 | 原本、取得応答、正規化表、対応表、再配布判断 | 原本は案件保管またはobject storage、台帳はGit |
| 4. 成果生成 | 共通schema、3ページ、Word/CSV、検証契約 | 検証済み国別bundle、サイト、Word、公開receipt | 国別案件ディレクトリと指定hosting |

層1のうち、JICA優先性、ISO/M49、所管事務所、DAC区分は142件すべてを先に保持する。さらに全142件へ、国別統計局・国勢調査、計画法・計画資料、行政コード・境界、国際データ候補の探索開始アドレスを持たせる。これは検索漏れを防ぐ入口であり、個別法令の本文確認や表の取得を完了済みとするものではない。所在確認、取得、内容確認、地理照合、指標採用を別状態にする。層2～4は国別案件で完成させ、機関や配布形式が似た国へアダプターを再利用する。公開国数と台帳登録数を同じ進捗値にしない。

## 担当範囲

### キット管理側で用意する

- 全country/areaの所在台帳と鮮度、アクセス条件、調査状態。
- 国勢調査、統計API、行政コード、境界、法令・手引き、計画・予算資料の取得アダプター。
- 原資料の全resource、全sheet、全table、全数値列を列挙するinventory処理。
- 地域コード、型、親子関係、境界版、有効期間の照合処理。
- schema変換、3ページ、Word、CSV、source listの決定的な生成処理。
- Lao、Uganda、DDPT等の代表fixtureによる操作・表示・文書の回帰検査。
- 最後の正常bundleを保持する更新・公開処理。

### 国別制作AIが行う

- 所在台帳を案件時点で再確認し、新版や改組を記録する。
- 定型アダプターを実行し、未対応形式だけ新しいアダプターとして追加する。
- 原表、説明、法令本文を読み、列・地域・定義・期間・利用条件の採否を記録する。
- 取得可能な地方資料を六テーマ、行政階層、年齢・性別、計画資料の区分ごとに探す。
- 検証済み候補から国別bundle、サイト、Wordを生成し、実画面と出力を確認する。

利用者がすることは、対象国、保存先、公開先、必要なら優先テーマを指定することである。資料を既に持っていれば追加証拠として渡せるが、公式情報源とデータをすべて事前収集することを開始条件にしない。

## Antigravity等の汎用AIに任せる範囲

汎用AIへは、自由なshell断片を多数実行させず、名前の付いた少数のプロジェクト内コマンドを使わせる。現行で利用できる開始・検証コマンドは次である。

```sh
node scripts/create-country.mjs --country "<country>" --out "<new-directory>"
npm run sources:plan -- --country <ISO3>
npm run sources:acquire -- --country <ISO3> --project <country-project>
node scripts/validate-country.mjs --project "<country-directory>"
node scripts/build-country.mjs --project "<country-directory>"
node scripts/verify-delivery.mjs --project "<country-directory>"
```

今後追加する国別アダプターも、URLごとの`node -e fetch(...)`ではなく、国・source・出力先を引数にする一つのコマンドにまとめる。これにより、実行許可は内容を読める固定script単位にでき、同じ会話で長い動的コマンドへの確認が繰り返される問題を減らせる。

汎用AIはcandidate作成には使えるが、次の操作を自己申告だけで完了扱いにしない。

- 法令名、条番号、計画義務、承認状態を`content_verified`へ上げること。
- 最初に見つかったCSVだけで国勢調査全体の探索を終了すること。
- 地方値のない国際系列を地方データとして補完すること。
- validatorの成功だけでsource内容、サイト操作、Wordの内容を合格にすること。
- 公開先の最後の正常版を未検証candidateで置換すること。

## Antigravityで確認した失敗を止めるゲート

### 1. 原本同一性

異なるsource IDが同じ`raw_path`とSHA-256を持つ場合、検証を失敗させる。同じ原本の意図的な別名だけ、内容を確認したうえで`artifact_alias_of`に元source IDを指定する。国勢調査PDFを地方行政法として登録したLao試作の誤りは、この検査で停止する。

`content_verified`にはsource ID、実原本、hash、ページ・表・節のlocator、確認した内容が必要である。法令の条番号を使う場合、該当見出しと本文を原本で確認する。リンク先ページの題名、publisher、MIME、保存ファイル名、本文fingerprintの不一致は候補を止める。

### 2. 取得resourceの取りこぼし

取得ページに列挙された全resourceと、取得したPDF/Excel/APIの全表・sheet・数値列へ、`adopted / rejected / not_applicable / pending`の判断を付ける。次のような状態はdelivery gateを通さない。

- 年齢・性別表を取得済みなのに対象地域の人口ピラミッドが0件。
- WDI応答を保存済みなのに、採用または不採用の記録がない。
- ADM0、ADM1、ADM2のいずれか一つを取得しただけで他のresourceを未確認。
- 法令リンクだけを保存し、本文、該当箇所、制度上の意味を未確認。

### 3. データ・地理・UIの一体検査

代表国と、データが十分な地域、部分的な地域、最下位地域をfixtureにする。次をbrowser回帰検査する。

- 地域診断からテーマ診断へ、親の範囲と子の比較階層が維持される。
- 比較対象エリアと表示階層のドロップダウンが地図・表・URLへ連動する。
- 欠測の選択地域と、値を持つ子地域の比較地図を別の事実として表示する。
- 50～400%のズーム、100%復帰、上位行政区、全国表示が機能する。
- 直接URL、戻る・進む、再読込、不正なIDでも例外画面にならない。
- Web、Word、CSVの地域、値、年、単位、出典、計算状態が一致する。

## 優先waveの決め方

優先国の母集団は、JICA公式の地域別海外事務所一覧で`Purview`に指定された142か国・地域とする。事務所所在国だけでなく全兼轄国を含む。一方、Purviewのない欧米連絡拠点の所在国を、所在だけで協力対象へ追加しない。2026-09-16取得版の内訳は、OECD DAC 2024年ODA受取国132、それ以外の協力パートナー10である。チリとウルグアイも除外しない。正は[`config/jica-priority-country-registry.json`](../config/jica-priority-country-registry.json)と[調査記録](research/jica-priority-2026/JICA_PRIORITY_142.md)である。

1. JICA優先142か国・地域の中から、法制度や地方統計の利用目的が明確な国を選ぶ。
2. 地域階層と公式コードが異なる国を混ぜ、アダプターを一国専用にしすぎない。
3. source形式がHTML、PDF、Excel、API、GISに分かれるようにする。
4. 各waveで、所在台帳、取得アダプター、完成bundle、検証記録を別々に数える。
5. wave完了後に失敗例を共通gateへ戻し、次の国へ進む。

先行整備として、JICA優先142件の優先・コード台帳と4区分の探索開始アドレス、国名一つの共通プロンプト、4つの基準国ケースを保持する。詳細source記録と取得アダプターは国別作成で追加し、完成見本を増やしながらsource family単位で横展開する。優先台帳や探索開始アドレスの完成は142国のサイト完成を意味しない。

## 完了の判定

国別サイトは、所在台帳の登録や初期生成では完成しない。原資料inventory、地域照合、六テーマ調査、計画制度・資料、population pyramidの採否、3ページ、Word/CSV、実画面、source list、delivery gateが揃って完成となる。

全世界整備の進捗は、少なくとも次を別の数字で示す。

- 所在台帳登録国数。
- 案件時点で所在を再確認した国数。
- 取得アダプターがある国・source family数。
- 地理照合済みの国数。
- delivery gate合格国数。
- 公開・更新確認済みの国数。
